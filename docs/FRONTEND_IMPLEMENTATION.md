# Frontend Implementation Overview

## Architecture
- **Framework**: React (v18) with Vite as the build tool.
- **State Management**: Global filter state is handled by a custom `FilterContext` (React Context API).  The context stores:
  - `dateRange` (start / end dates)
  - `shift`, `equipmentType`, `materialCategory`
  - Export‑handler registration for the currently active dashboard view.
- **Routing**: `react-router-dom` (v6) configured in `src/App.jsx`.  Each major analytical module is a separate route/component under the `/dashboard` base path.
- **API Layer**: Centralised Axios instance in `src/services/api.js` with helper functions for all backend endpoints (KPIs, production, equipment, downtime, haulage, etc.).
- **Styling**: Existing CSS design system (variables, glass‑card, dark/light theme) extended with utility classes for grids, badges, export button and active navigation tabs.
- **Charts**: `recharts` library is used for line, bar, area, stacked bar and radar visualisations.
- **Export**: CSV export util (`src/utils/exportCsv.js`).  Each view registers an export handler via `FilterContext.registerExportHandler`.  The global **Export** button in `FiltersBar` triggers the handler for the active view, producing a filename that includes the selected date range.

## Data Flow
1. `FiltersBar` updates the filter context.
2. Each view uses `useEffect` to call the appropriate API functions, passing the current filter values as query parameters.
3. API responses are stored in component local state (`useState`).  Loading, empty and error states are rendered conditionally.
4. When the Export button is clicked, `FilterContext.triggerExport()` invokes the handler registered by the active view.  The handler uses the latest data from the view to generate a CSV via `exportCsv` and triggers a download.

## Build & Deployment
- Development: `npm run dev` (Vite dev server on `http://localhost:5173`).
- Production build: `npm run build` creates optimized static assets in `dist/`.
- The generated `dist/` can be served by any static file server or integrated into the existing Express backend (`/frontend` static route).

## Extensibility Guidelines
- **Adding a new module**: Create a new component, add a route in `App.jsx`, consume `FilterContext`, and register an export handler if needed.
- **New API endpoint**: Extend `src/services/api.js` with a wrapper function; keep naming consistent with existing functions.
- **Styling**: Add new CSS classes to `src/style.css` using existing variable naming conventions to preserve theme consistency.
